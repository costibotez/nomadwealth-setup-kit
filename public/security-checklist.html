Setup Kit / Security checklist

After setup

Close the easy doors.

Print this page or work through it in your own notes. The checklist has no interactive state and sends nothing anywhere.

Never record the actual values on this page. Check the control, not the secret.

Account and source

  • The deployed source is in a private GitHub repository or private source control project.
  • Vercel two-factor authentication is enabled for every person with project access.
  • Neon two-factor authentication is enabled and the database owner list is reviewed.
  • No .env, database dump, CSV, or spreadsheet is committed to Git.

Application

  • The owner password is long, unique, and stored in a password manager.
  • Two-factor authentication is enabled in NomadWealth when available.
  • You tested “log out all devices” and know where to revoke sessions.
  • SETUP_TOKEN was removed or rotated after first-run setup, according to your operating preference.
  • Only buyer-owned optional providers are enabled, and each has a documented key-rotation path.

Database and recovery

  • Neon point-in-time restore is enabled or another tested backup exists.
  • A restore procedure has been written down without embedding credentials.
  • You have tested a harmless preview deployment before updating Production.
  • A recent export or backup is stored separately from the live database.

Sharing and support

  • Read-only share links are scoped, expiring where appropriate, and never treated as authentication.
  • Support requests contain error messages without connection strings, keys, balances, or customer records.
  • If any secret appeared in a log, screenshot, chat, or repository, it was rotated rather than merely deleted.
