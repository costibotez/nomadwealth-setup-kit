Setup Kit / Updating

10 / Maintain

Update like you own the stack.

New releases can include application changes and database migrations. Use a deliberate deploy, check the result, and keep a recovery path.

Before updating

  • Confirm you can log in and that your recovery methods work.
  • Enable Neon point-in-time restore and take a backup before a bulk change.
  • Review release notes for migrations, required variables, and breaking changes.
  • Make sure you know which Vercel environment is Production.

Deploy the update

  1. Review the source change

    Pull or merge the release into the private repository that owns your Vercel deployment. Never copy an environment file into the repository.

  2. Deploy a preview first

    Use a Vercel Preview deployment when possible. Check that the build succeeds and that the app does not reveal a missing migration or variable error.

  3. Promote deliberately

    Promote to Production after the preview and backup checks. Configured installs apply embedded runtime migrations on the first request after a release, before affected reads.

  4. Verify the cockpit

    Log in, open the dashboard, inspect a few known records, test an import preview, and check scheduled jobs if you use them.

If something goes wrong

Pause rather than repeatedly redeploying. Check the Vercel deployment logs, compare environment variables, and use Neon restore or a previous known-good deployment according to the release notes. Keep the original database backup and avoid destructive SQL copied from an online answer.

Updates are free for life on Lite and Pro. A Pro key does not expire because you update the application.
